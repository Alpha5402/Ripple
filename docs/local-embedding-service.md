# 桌面 App 本地 Embedding 服务

在「设置 → Embedding 模型」选择本地 WeMM 服务，点击「启动本地服务并连接」。App 会启动已安装的 Python 环境、等待模型就绪，再用固定测试文本验证连接。已有兼容服务时显示「连接本地服务」，直接复用。

开启「打开 App 时自动启动本地服务」后，重新打开 Ripple 会恢复服务；这是 App 启动时恢复，不是操作系统登录项。已开启的自动增量索引会在服务就绪后继续处理待索引内容。退出 App 只停止由它启动的子进程，不停止终端或其他应用启动的服务。

运行环境复用现有 `wemm` 目录（包含 `venv` 和固定版本 `models`），不会自动下载模型。优先使用保存的目录，再查找配置位置和应用上级目录中的 `.ripple/wemm`。找不到时展开「运行环境与启动日志」选择已安装的目录。移动 App 后已保存的绝对目录继续有效；移动或删除模型目录后需要重新选择。

服务管理偏好保存在 App 状态目录的 `local-embedding.json`，与工作区的模型连接和索引设置分别保存。打包内置服务脚本位于 `app.asar.unpacked/wemm/server.py`，Python 和模型仍保留在外部运行环境中。

服务仅绑定 `127.0.0.1:8787`。启动失败或超时会显示日志并清理所启动的进程，可再次点击重试。遇到其他服务占用端口时不会替换它。浏览器版不能启动本机进程，需要先通过 App 或终端运行服务。
