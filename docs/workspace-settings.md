# 工作区设置

侧栏「设置…」打开独立设置页，包含「知识范围」与「Embedding 模型」。规则按当前工作区保存在本机，重启后恢复；不修改知识库的源文件。

## 排除目录与文件

在「知识范围 → 排除规则」中每行填写一条规则，例如：

```gitignore
# 不纳入构建的资料和草稿
Sources/
archive/
**/drafts/
*.tmp.md

# 只排除根目录下的附件目录
/attachments/

# 保留某个目录中的一篇说明
notes/*
!notes/overview.md
```

匹配规则使用 [node-ignore](https://github.com/kaelzhang/node-ignore) 的 gitignore 语义，区分大小写，路径相对于工作区根目录。`目录/` 可匹配任意层级同名目录；`/目录/` 仅匹配根目录；`*`、`**`、`?`、注释及 `!` 例外均可使用。父目录已排除时不能只用单文件例外重新纳入，需要先恢复父目录或改成 `目录/*`。

现有扫描规则仍跳过点号目录、符号链接（桌面）以及 `AGENTS.md`。本次设置不自动读取项目的 `.gitignore`，以免把版本控制意图误当成知识范围。

「保存并应用」会立即重新计算知识范围：被排除笔记不参与实体名称解析、Mention/WikiLink 关系、搜索和向量索引；已缓存的各个模型空间中的对应向量会删除，之后的索引任务不会将其重新发布。其他笔记中的文字和 WikiLink 语法保持原样，指向被排除文档的链接显示为未解析目标，不生成关系边。

桌面版在扫描阶段跳过匹配目录，不读取其中正文。新增文件、自动同步、重启和重新扫描均使用相同规则。设置保存在工作区状态目录的 `knowledge-settings.json`；只读打开的知识目录也能调整这些本机设置。

浏览器版在可访问目录的扫描阶段应用同样规则。已导入后才排除的笔记会保留一份本地文本副本，用于撤销排除与保留本地编辑；副本不属于引用或向量索引。未导入的内容需同步原目录后才能重新纳入。纯上传目录快照需要重新选择目录同步。规则和本地副本存入同一工作区的 IndexedDB 快照，两个工作区的设置互不影响。

全部排除后仍可从「设置知识范围」入口撤销规则。重新纳入的笔记重建确定性关系；如果自动索引开启且模型可用，会补建其向量，否则点击更新索引。

## Embedding 模型

「Embedding 模型」统一管理服务类型、地址、模型、认证、分块大小、批次大小、质量下限和自动增量索引。模型连接先进行固定测试文本的探测，知识范围规则在实际笔记索引前生效。原有认证存储方式保持不变。

## 验证

自动化覆盖 gitignore 目录/根路径/通配符/例外语义、排除发生在正文读取前、引用/搜索与多个模型缓存清理、后续发布不复活旧向量、桌面重启、全部排除后恢复、浏览器快照恢复及同步防止重新纳入、浏览器目录遍历短路。桌面 UI 使用只读 fixture 实际检查了设置页和保存排除规则的操作。
