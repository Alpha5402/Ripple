# K5 / K6：评估与内核稳定化

本轮继续完善内核，不进入 Desktop/Web 产品界面。源 iWiki 保持只读；运行数据、模型缓存和私有评估报告写入项目忽略目录。

## K5：可复跑的关系评估

- 建立 200～400 对分级参考样本，包含同名异义、相似术语和相似型号的难负例；标签记录来源与理由。
- 明确开发集和测试集，先固定数据再运行模型，不用最终测试标签选择权重。
- 在完全相同候选池和预算下比较 Mention+Explicit、Semantic、Hybrid，输出 P@K、nDCG、展示阈值下的误召回及逐例差异。
- 使用真实本地 WeMM 生成评估向量；保留反例，并输出真实 iWiki 的待人工标注队列。
- 合成参考标签与人工认可分开记录；“事后有用的新发现”只有用户标注后才能算成立。

## K6：可持久化、可测量的独立内核

- SQLite 事务存储文档、修订、用户声明和可重建向量缓存，提供 schema 检查与并发写冲突检测。
- FTS5 对中文进行分词；代码符号、精确型号走原文精确匹配，避免语义相似代替字面身份。
- 将名字匹配和文档导入改为索引操作，缓存未变文档的引用；语义计算改为按中心按需执行，避免每次发布全库两两配对。
- 固化 capability、coverage 和错误协议；补齐 SDK 文档与第二个最小 HTTP Host。
- 运行 1k / 5k / 10k 文档测试，分别记录导入、重启、Snapshot、Lens 和增量延迟；语义规模测试标明合成向量，不能冒充万篇真实模型编码。

每一阶段均保留可复查产物。最终报告分别说明运行正确性、评估观察与尚需人工标注的结论。
