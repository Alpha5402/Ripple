# ADR 0001：确定性内核与宿主分离

状态：本次 K1–K3 实现已采用。

## 背景

设计基线 1.1 要求先交付可脱离 UI 运行的知识内核。用户进一步确认，单向提及应支持双向发现，并提供现有 iWiki 作为只读试验田。

## 决定

1. Core 只依赖领域类型和端口，不导入具体解析器、存储、文件系统、模型或宿主。SDK 的会话管理也保持纯 TypeScript。Node 组合入口显式导入适配器。
2. 用 Markdown AST 限定可匹配范围，WikiLink 和自然提及分别形成信号；原文不改写。身份、用户声明与派生索引分开保存。
3. 关系按文档对聚合、双向可查，但信号保留方向。一跳候选只由中心与邻居的直接关系决定。Lens 只改变阈值，不进行多跳遍历。
4. Snapshot 冻结候选和评分；使用实时有效性索引撤回已失效证据，普通新增候选等待显式刷新。滑条查询只检查候选，不在每一档重新扫描全库提及。
5. 当前同步导入重建全局提及/关系，优先覆盖新增、删除、改名、改别名引起的跨文档依赖。未变 Markdown 不重新解析。SQLite、异步 Embedding 和大库增量优化留待后续里程碑。

## 代价与验收

新增实体可能影响任何旧正文，本阶段的重建成本较高，但更新语义清晰。CLI 的本地元数据按单进程保存，不解决多宿主并发写入。没有语义模型时，召回范围只覆盖已存在的确定关系。

以固定合成样本测试歧义、评分和探索不变量；以 iWiki 检查实际路径解析、证据定位、历史与源文件哈希；以独立 SDK 验收脚本和导入边界测试证明 Core 不绑定 CLI。运行结果不等于推荐质量或交互收益已验证。
