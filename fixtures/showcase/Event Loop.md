# Event Loop

Event Loop 让浏览器协调脚本、事件、网络通知和渲染机会。它不是一个简单的「所有回调排成一条队」的模型：任务来源、微任务检查点与渲染步骤各有职责。

## 一次执行之后

JavaScript 任务在当前调用栈清空前，不会被另一个普通任务从中间切走。任务结束后，浏览器可能执行微任务检查点，再决定是否更新渲染。

Promise 的反应与 `queueMicrotask` 都会进入 Microtask 队列。处理微任务期间加入的微任务，会在同一检查点继续执行；如果始终有新的微任务，其他工作可能长时间得不到机会。

```js
console.log('同步开始');
setTimeout(() => console.log('后续任务'), 0);
queueMicrotask(() => console.log('微任务'));
console.log('同步结束');
```

这段代码先输出两行同步日志，再输出微任务，最后才是计时器回调。`0` 表示计时条件，不保证立即执行。

## 把工作交还给浏览器

长时间占用主线程会推迟交互响应。把工作拆成小段，或者把适合迁移的计算放入 Web Workers，通常比把同步计算简单包进 Promise 更有意义。

Async-Await 可以暂停一个异步函数的后续执行，但恢复时机仍由 Promise 反应与微任务调度决定。
