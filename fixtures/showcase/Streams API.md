# Streams API

Streams API 把数据处理组织成持续产生和消费的块。数据不必全部到齐后才能开始处理，读取、转换与写入可以逐步进行。

## 生产与消费的节奏

一个流可能产生得很快，而下游写入较慢。无限缓存会带来内存压力，因此流需要表达下游还能接收多少数据。

```js
await readable
  .pipeThrough(new TextDecoderStream())
  .pipeTo(writable);
```

管道把读取、转换和写入连接起来，并传播相关的关闭与错误状态。Backpressure 用于协调上下游速度，避免生产方持续压过消费方。

## 资源有明确生命周期

读者取消读取、写入方失败或处理链关闭时，需要让相邻环节有机会清理资源。不要只考虑成功输出，还要考虑结束过程。

Fetch 的响应正文可以作为流来消费。分块处理适合渐进展示，但解析器仍须处理一个逻辑记录跨越多个块的情况。
